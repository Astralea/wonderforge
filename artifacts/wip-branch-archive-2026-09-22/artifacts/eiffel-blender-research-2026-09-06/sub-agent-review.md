# Eiffel asset and construction review

Completed by the in-session `eiffel_asset_review` sub-agent after the owner superseded earlier model-specific delegation instructions. Read-only code review; no edits, tests, Blender calls, or browser captures were performed by the reviewer.

1. **Moving and seated geometry differ.** Climbing chords use post thickness 0.29 instead of 0.22, and climbing braces use web width 0.62 instead of 0.4. Seated batches select the climbing variants; active pools select only by kind and use the lower defaults. Use the same geometry key for both phases. [Constants](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelStoneSystem.ts:32), [seated variants](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelStoneSystem.ts:276), [active creation](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelStoneSystem.ts:292).

2. **Contact coverage checks a scalar convention, not rendered geometry.** The engine returns dimensions[1]/2 and the haul test subtracts the same value. Render transforms also apply kind-dependent alignment and dimensional scaling. Imported offsets or envelopes need independently transformed contact samples. This does not establish that every current part floats. [Helper](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/engine/eiffelConstruction.ts:46), [test](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/tests/eiffel-construction.test.ts:110), [transforms](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelStoneSystem.ts:47).

3. **Asset completion has no production repaint hook.** EiffelWorld exposes readiness, but WorldScene and ThreeCanvas do not consume it. Loading after a paused frame has no completion-triggered repaint. The asynchronous Palais attachment also lacks a disposal check after awaiting the load. These are code-path findings, not browser-reproduced failures or measured GPU leaks. [Readiness](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelWorld.ts:27), [world creation](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/WorldScene.ts:66), [frame scheduling](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/ThreeCanvas.tsx:52), [attachment](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelEnvironment.ts:227), [disposal](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelEnvironment.ts:958).

4. **Reuse the existing instancing boundary.** Both moving and seated parts already use InstancedMesh. Share imported geometry across their corresponding batches instead of cloning entire GLB scenes. Explicitly account for ownership when replacing imported materials; overwriting those materials alone does not prove a GPU leak. [Batches](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelStoneSystem.ts:246), [active pool](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/EiffelStoneSystem.ts:295), [material replacement](/Users/hina/Documents/Experience-Intelligence-Domain/wonderforge/src/render/three/eiffelPalais.ts:30).

Recommended first experiment: export one asymmetrical lower-leg chord and one diagonal with geometry keys, bounds, and lifting/contact anchors. Drive both through the existing absolute-time graph in an isolated preview with identical moving/seated geometry. Check axes, dimensions, transformed contact, seating continuity, reverse seeks, and delayed-load repaint/disposal before expanding to a full bay.
